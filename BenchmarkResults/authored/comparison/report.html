Capability and authoring differences

VFX Graph: a real graph contains the configured ribbon and secondary streams. Shared input uses a 64-byte ability record; per-ability input uses component properties. Automatic instance batching is tested enabled and disabled. Generated graph topology follows the selected library. Gradients, curves and texture profiles come from the same baked catalog as the CPU renderers.

LineRenderer, Burst mesh and procedural ribbons: configured ribbon slots use the named renderer. Secondary modules use an explicitly measured procedural GPU companion. A combined effect is a hybrid implementation; its complete cost cannot be attributed to the ribbon renderer alone.

Shuriken: native particle streams reproduce the same analytic motion. Shared/per-ability systems, ordinary mesh particles, GPU-instanced mesh particles and direct Burst particle jobs are measured independently. Ground-oriented streams use mesh particles when billboards cannot represent their orientation.

Multiple ribbon modules require multiple LineRenderers per ability, whereas a VFX graph packages its configured streams inside one component. This practical packaging difference is part of the comparison. Reusable assets supply path algorithms, ribbon profiles, gradients, curves and secondary motion modules.

Methodology and limits

Visible release Windows player, Burst AOT, no VSync or frame cap. Each technique sees the same environment, endpoint sequence, fixed 60 Hz simulation and native Begin/Follow/Release jobs. Baseline includes that environment and command/strand-preparation work. Technique order is shuffled within each configuration/repetition. The protocol above states this run's actual cell count and frame durations; the immutable suite manifest lists every cell. Warmup and shader first use are outside the timed interval; pool setup is recorded separately. Lifecycle sampling spans pooled release tails and reuse, with staggered phases.

CPU bridge times include job completion and engine calls, plus the last completed Shuriken callback. They exclude later engine work. Compare main/render frame times too. GPU deltas subtract paired whole-frame baselines; they are not isolated-pass timestamps. CPU times are wall time, not summed active core cycles. CPU and GPU frame times overlap; do not add them. Alpha-zero fixed slots still execute; no active compaction is credited. Lifecycle results apply to these exact implementations. Color32 quantization and LineRenderer gradient/connected-join differences remain. Release builds can lack GC counters. Total memory and bulk input bytes are exported in the aggregate CSV; neither is isolated effect VRAM or measured bus traffic.

The arena is a visual proof of concept with a fixed six-unit environment. Stress links in Sustain fill the same 36×19 m footprint at every count. Spread uses a fixed wider 180x95 m footprint and a wider camera at every count. Lines are smaller on screen in Spread. These are separate density workloads; their difference is not an isolated CPU measurement. This does not simulate a complete RTS with hundreds of animated units, AI, terrain streaming or contested GPU resources. No depth collision, history-based smoke, distortion, dynamic effect lights, trails following arbitrary historical paths or multiple cameras are included. Particles follow deterministic analytic trajectories so all backends can reproduce the same effect. Those capabilities require further real-game tests.
