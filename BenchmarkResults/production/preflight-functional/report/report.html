Capability and authoring differences

VFX Graph: all five GPU systems live in one real graph asset, with shared or per-ability input. Per-ability graphs are tested with automatic instance batching both disabled and enabled. The graph exposes SpawnCore, SpawnLayer0–3, Start, End, Tint, Shape, Clock and CameraPosition. Shared graphs consume a 64-byte ability record. Capacity variants avoid a huge fixed pool at low counts.

LineRenderer, Burst mesh and procedural ribbons: the three ribbon strands use their corresponding renderer. Free motes, sparks, coronas and ground runes use a four-layer procedural GPU companion. This is an explicit hybrid implementation. These techniques do not gain particle systems merely by rendering a line.

Shuriken: native particle layers provide the same secondary geometry. Shared/per-line systems, ordinary mesh particles, GPU-instanced mesh particles and direct Burst particle jobs are measured independently. The per-line variant packs all three strands into one core system and has four secondary systems per ability. Mesh ground runes accompany the billboard variants because a view-facing billboard cannot represent the ground orientation.

Three stacked ribbons are needed for these authored cores. Consequently a LineRenderer ability uses three LineRenderers, while a complete VFX ability still uses one component/graph containing five systems. That packaging difference is part of the practical comparison.

Methodology and limits

Visible release Windows player, Burst AOT, no VSync or frame cap. Each technique sees the same environment, endpoint sequence, fixed 60 Hz simulation and native Begin/Follow/Release jobs. Baseline includes that environment and command/strand-preparation work. Technique order is shuffled within each configuration/repetition. The full matrix has 360 cells and three repetitions. Warmup and shader first use are outside the timed interval; pool setup is recorded separately. Lifecycle sampling spans pooled release tails and reuse, with staggered phases.

CPU bridge times include job completion and engine calls, plus the last completed Shuriken callback. They exclude later engine work. Compare main/render frame times too. GPU deltas subtract paired whole-frame baselines; they are not isolated-pass timestamps. CPU times are wall time, not summed active core cycles. Alpha-zero fixed slots still execute; no active compaction is credited. Color32 quantization and LineRenderer gradient/connected-join differences remain. Release builds can lack GC counters. Total memory and bulk input bytes are exported in the aggregate CSV; neither is isolated effect VRAM or measured bus traffic.

The arena is a visual proof of concept with a fixed six-unit environment. Stress links fill the same 36×19 m footprint at every count; this does not simulate a complete RTS with hundreds of animated units, AI, terrain streaming or contested GPU resources. No depth collision, history-based smoke, distortion, dynamic effect lights, trails following arbitrary historical paths or multiple cameras are included. Particles follow deterministic analytic trajectories so all backends can reproduce the same effect. Those capabilities require further real-game tests.
